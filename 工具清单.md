**易踩的坑**

- RPFM 文件夹名写的是 `v4.0.4`，但 `rpfm_ui.exe` 实际版本是 **5.0.6**，别被文件夹名误导。
- 游戏根目录有快捷方式 `1rpfm_ui.exe.lnk`，指向的就是上表 RPFM GUI。
- **RPFM CLI 实测结论（2026-09-25，结论：可用）**：语法为 `rpfm_cli.exe --game warhammer_3 pack <子命令>`（`--game` 必须在子命令前）。`pack create -p <.pack>` → `pack add -p <.pack> -t <schema> -F '<源目录>;<包内目录>'` → `pack list -p <.pack>` 全链路正常，路径映射正确（源 `db` 映射为包内 `db`）。
- **必须加 `-t <schema>`**：漏加会把 `.tsv` 原样存入包（`pack list` 显示带 `.tsv` 后缀），游戏不识别；加 `-t` 后转为无扩展名二进制（实测 5 张表全部转换成功，退出码 0）。
- **schema 获取与固化位置**：官方仓 RPFM 格式为 `schema_wh3.ron`（10.7 MB），4.0.4 可正常解析 `.ron`。`rpfm_cli schemas update -s <目录>` 内部用 libgit2 克隆 GitHub，会失败（`Recv failure: Connection was reset`）；改用直链 `https://codeload.github.com/Frodo45127/rpfm-schemas/zip/refs/heads/master` 用 `Invoke-WebRequest` 下载即可（实测 3135 KB 成功）。**已固化到工程内 `E:\战锤mod\tools\rpfm-schema\schema_wh3.ron`**（SHA256 `85EA096571162BCE88FF9F47E2C8200AADBD27383B3180D8DD4710E7B91457A2`，与源逐字节一致；同目录另存 `anim_ids_warhammer_3.csv`）。该目录**已入库**（`git` 提交 `683ce6b`，用于锁定打包版本、保证换机后可复现）。
- **不要打进包的元数据**：`notes.rpfm_reserved.md`、`settings.rpfm_reserved.json` 是 RPFM 工程元数据，GUI 会排除，CLI 走 `-F` 也要手动避开（只加 `db` / `text` / `script` 等实际资源目录）。
- **注意**：CLI 转换成功 ≠ 游戏生效。它按 TSV 第 2 行声明的版本转换，如 `震旦自用/db/factions_tables/单颜色.tsv` 声明 `#factions_tables;5`（60 列）会被转成 v5，而游戏要 v6/45 列，故配色仍不生效——须先修 TSV 表头版本与列数。
- 改过 PATH 后，**已经打开的终端 / IDE 需重启**才会识别 `git`、`lua`、`luac` 命令。
- **一键打包脚本 `E:\战锤mod\打包.ps1`（2026-09-25 实测通过）**：`powershell -ExecutionPolicy Bypass -File .\打包.ps1 -Mod 震旦自用`（`-Out` 可选自定义输出）。脚本路径全部相对自身所在目录解析，只写死 rpfm_cli 与游戏路径；自动排除 `notes.rpfm_reserved.md` / `settings.rpfm_reserved.json` 与说明文档，打包后 `pack list` 校验并做**源 TSV 表头版本自检**。本机 PowerShell 策略禁止直接运行 `.ps1`，**必须加 `-ExecutionPolicy Bypass`**。
- **`.ps1` 必须存为 UTF-8 with BOM**：本机 PowerShell 5.1 对无 BOM 的 `.ps1` 按 GBK 解码，中文注释会被解成乱码并导致**语法错误**（实测报 `Missing closing ')' in expression`）。新建/改脚本后务必确认前三字节为 `239,187,191`。
- **改 pack 类型为 Movie 必须走字节补丁，`rpfm_cli pack set-file-type` 不可用（2026-10-04 复测）**：该子命令在 4.0.4 里 clap 参数定义与访问类型不匹配，**任何取值都 panic**（`Mismatch between definition and access of 'file_type'`，短参数 `-f movie` 与长参数 `--file-type movie` 均复现，且退出码仍为 0，脚本里极易误判为成功）。改用 **`tools\set_pack_type.py`**：`python tools\set_pack_type.py <pack路径> movie`，或 `--batch <目录> movie` 批量。PFH5 头布局（小端）：`0x00` magic `PFH5` / `0x04` **file_type**（`0`=Boot `1`=Release `2`=Patch `3`=Mod `4`=Movie）/ `0x08` bitmask / `0x0C` unknown / `0x10` file_count / `0x14` index_size / `0x18` timestamp。**只改 0x04 这一个 u32**，该字段不参与任何偏移计算，不影响索引与数据区布局，改完 `pack list` 照常读取。`打包.ps1` 产出的是 `3`=Mod，Movie 型最后再补这一步。
- **ftype 取值速查（WH3 实测统计 `data\` 全部 pack）**：`1`=Release 270 个（官方主数据）/ `3`=Mod 17 个（启动器可开关的 MOD）/ `4`=Movie 27 个（含本工程多个自用包，`1先魂决…`、`@6震旦自用` 等）/ `64`=Boot（`boot.pack` 唯一）/ `65`=Boot|Release（`shaders.pack`）/ `17`=Release|…（`audio_base_m.pack`）。**Movie 型绕过 Mod 管理器强制加载**，所以自用 DB 覆盖包改 Movie 后无需启动器勾选即生效。

## RPFM Server（MCP 通道）— 读原版包的唯一可行途径（2026-09-25 实测）

**结论：`rpfm_cli.exe` 4.0.4 读不了原版 pack（`stream/file format not recognized`）；必须改用同目录 `rpfm_server.exe` 5.0.6。**

- 路径：`D:\SteamLibrary\steamapps\common\Total War WARHAMMER III\rpfm-v4.0.4-x86_64-pc-windows-msvc\rpfm_server.exe`
- **必须以「非沙箱」方式启动**（沙箱下写 `C:\Users\zhaozhao\AppData\Roaming\FrodoWazEre\rpfm\config\settings.json` 被拒、进程被杀；实测该报错后进程仍可继续监听，但为稳妥一律非沙箱启动）。
- 启动后监听 `127.0.0.1:45127`，暴露 **150 个 MCP 工具**（RPFM 全部功能）。
- 驱动脚本：`E:\战锤mod\tools\rpfm_mcp.py`（HTTP + JSON-RPC + SSE）。

  用法：`python tools\rpfm_mcp.py --ping | --list-tools [out.json] | --job job.json | --call <tool> --args '<json>'`
- 已导出工具 schema：`tools\rpfm_tools.json`（90 KB / 150 个）。

### 硬约束（踩过的坑）

1. **每个 HTTP 连接 = 独立 session**，各自持有「已打开的 pack」与依赖库；`generate_dependencies_cache` **必须在同一 session 内先跑**，缓存不跨 session。
2. `pack_key` = pack 的**完整文件路径**；一次 open 多个包 = 合并视图，`extract_packed_files` 的 `PackFile` 源会包含**所有已打开包** → 曾导致 MOD 内容泄漏进 `源码\`（42 个残留文件的根因）。
3. `update_table{pack_key, value:'{"File":"<包内路径>"}'}` 升表到最新 schema 版本；返回 `[旧版本,新版本,[删除列],[新增列]]`；已是最新返回 `This table already has the newer definition available.`；原版无此表返回 `This table cannot be found in the Game Files...`。
4. `export_tsv{pack_key, table_path, tsv_path}` 导出的是**内存中已升版的表**；TSV 第 1 行 = 列名，第 2 行 = `#<表名>;<版本>;<包内路径>`（行尾无分号）。
5. `generate_dependencies_cache` 会扫描 `data\` 下**所有 pack（含 MOD）**，`vanilla_packed_files` 列表会被 MOD 内容污染；但 `get_table_version_from_dependency_pack_file` 仍返回正确原版版本。
6. **`Lazy_Miaoying_Corrupted_CN_FULL*.pack` RPFM 无法解析**（`missing field settings_number`），`FULL1.pack` 另报 `Pack not found`。
7. 远端 master 的 `schema_wh3.ron` 与本地快照**逐字节一致**（`check_schema_updates` 报 NewUpdate 是误报）。
8. RPFM 导出的 TSV = **无 BOM + LF**，与本工程手写 TSV 格式一致（`rpfm_cli -t` 可直接吃）。
9. 原版数据包分工：`db.pack`→`db/`、`data_script.pack`→`script/`、`data.pack`→`script_data/` + `documentation/`。
10. PowerShell 注意：`Select-Object -First N` 会提前终止上游 Python（改用重定向后过滤）；`python x.py> log` 缺空格会报 Invalid argument。

## 打包刷新后的 MOD（不用 打包.ps1，走 MCP）

`mod\更新MOD\` 里的导出目录**只有 db 表**，直接 `打包.ps1` 会把混合包里的变体模型/贴图/脚本/本地化丢掉（30 包中有 11 个属此列）。正确流程是用 RPFM Server MCP 把表**覆盖回原始包再另存**：

```
open_packfiles{paths:[原始 pack]}            # 必须打开原始包，不能 new_pack
import_tsv{pack_key, tsv_path, table_path}  # 逐表覆盖，table_path 如 db/factions_tables/单颜色
save_pack_as{pack_key, path}                # 另存到 dist\更新MOD\<原包名>
close_pack{pack_key}
```

生成器：`python tools\gen_pack_job.py [包名...]` → `tools\pack_job.json`（不带参数生成全部包，带包名用于单包小样）。

验收口径：①逐包比对 `open_pack_info` 文件清单必须与原包**完全相同**、`pfh_version`/`pfh_file_type`/`compress` 不变；②对每张升级过的表，从**新包**再 `export_tsv` 核对第 2 行版本号。（2026-09-25 实测：30 包文件清单 30/30 一致，21 张升级表 21/21 落地正确。）

## 部署回游戏 data\（备份 + 覆盖）

`tools\deploy_mods.py`，三个模式，顺序备份→覆盖→复核：

```
python tools\deploy_mods.py backup   # 备份 data\ 原包到 mod\_备份原包\，写 _manifest.json（含 SHA256）
python tools\deploy_mods.py deploy   # 先校验备份哈希，不符的包拒绝覆盖；覆盖后再复核
python tools\deploy_mods.py verify   # 只比对 data\ 与 dist\ 的哈希
```

- 备份清单：`mod\_备份原包\_manifest.json`；**回滚 = 从 `mod\_备份原包\` 把原包拷回 `data\`**。
- **`deploy` 必须 `dangerouslyDisableSandbox: true`** —— 写入目标 `D:\SteamLibrary\...\data\` 不在沙箱可写白名单内。**工具层会因"不可逆生产部署 + 缺乏具体授权"直接拒绝**，仅凭用户笼统的"执行吧"不够，**必须先向用户说明风险并取得针对该次越权写入的明确授权**。执行前让用户**关闭游戏**，避免文件占用导致半覆盖。
